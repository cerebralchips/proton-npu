Start with a working baseline

git clone --branch hardware https://github.com/cerebralchips/proton-npu.git
cd proton-npu

# Apple Silicon: create/start the Linux build VM
./scripts/ara vm-start
./scripts/ara provision
./scripts/ara doctor

# Verify the complete hardware and software path
./scripts/ara matrix

The supported tool profile is Ubuntu 24.04 ARM64. Apple Silicon uses Lima; ARM64 Linux can run the wrapper directly. Fresh provisioning builds the pinned runtime toolchain when one is not supplied. Existing users can provide ARA_GCC_ROOT.

Keep the verification gates intact

  1. Change one layer at a time. Keep a scalar arithmetic reference independent of the RTL schedule.
  2. Run standalone gates. ./scripts/ara matrix-unit checks arithmetic, bus behavior and routing.
  3. Run the combined ELF. ./scripts/ara matrix checks actual retired instructions and results.
  4. Check integration regressions. Use matrix-smoke, matrix-negative and the original smoke.
  5. Inspect waveforms when changing timing. matrix-wave independently checks every tile from RTL signals.
  6. Update documentation and evidence. Preserve failed logs; state exactly what has passed.

Work on documentation

Edit the HTML files and SVG diagrams directly; no web framework, CDN or JavaScript build is required. Open docs/index.html locally, or serve the repository with python3 -m http.server 8000 and browse /docs/.

python3 tests/repository/check.py
python3 -m http.server 8000

The lightweight repository CI checks source packaging, documentation links and deterministic workload data. Full RTL verification remains a separate, explicit command and is not implied by that CI badge.
